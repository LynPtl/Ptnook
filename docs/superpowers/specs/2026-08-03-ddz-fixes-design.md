# 斗地主体验修复（本地测试反馈）— 设计文档

日期：2026-08-03
项目：Ptnook 聊天室斗地主（feat/ddz 分支，src/worker.js 含 ChatRoom DO 状态机 + 内联前端，src/ddz.js 引擎）

## 背景

三人斗地主本地测试后，用户提出 6 条修改（4 个 bug + 2 个体验增强）。本 spec 覆盖这一批修改，不改变已定的核心规则。

## 修改项

### 1.（bug）两连过后轮回出牌者点「过」的错误文案
现状:出牌校验里,自由出(lastPlay 为 null)时点「过」报"首出不能过"。但两家连过、出牌权回到最后出牌者时也是 lastPlay=null,此时报"首出不能过"不准确(这不是首出)。
改法:文案改为通用的「本轮到你先出，不能过」(既覆盖真首出,也覆盖两连过后的自由出)。行为不变(自由出确实不能过),仅文案修正。

### 2.（bug）结算后手牌条仍显示牌
现状:某玩家打出最后一张进入 settled 后,前端手牌条(#ddzhand)仍显示旧牌。
改法:前端在收到 phase==="settled" 的 ddz_state 时,清空自己的手牌条(#ddzhand 置空,ddz.hand=[])。结算阶段不再显示可点手牌。

### 3.（增强）结算时展示各家剩余手牌
现状:结算只广播输赢和积分。
改法:settle 时,在结算 system 广播中附上每家剩余手牌(赢家为空)。格式示例:
`本局结束，地主胜。剩余手牌 — 小明：无；小红：5 8 K；小刚：3 3 Q。小明 +4（累计 4），…`
注:结算是牌局结束,亮所有人剩余牌无隐私问题。手牌用点数/小王大王文字。

### 4.（增强）每次出牌/过牌广播附三家剩余张数
现状:出牌广播"X 出 ...",过牌广播"X 过",不含剩余张数。
改法(方案 C，不做手数编号):
- 出牌广播格式:`X 出 <牌> ｜ 剩余 小明5 小红8 小刚3`。
- 过牌广播格式:`X 过 ｜ 剩余 小明5 小红8 小刚3`。
- 剩余张数按座位顺序列出所有三家。不引入手数/轮次编号。

### 5.（增强）再来一局轮换先叫分
现状:再来一局(startBidding)的 bidOrder 固定为 g.players 原顺序,bidTurn 恒为 players[0]。
改法:再来一局时,先叫分的人按座位顺序轮换——上一局首叫者的下一个座位先叫。
实现:记录上一局的首叫座位索引 g.firstBidIndex(首局随机或取 0);再来一局时 `firstBidIndex = (firstBidIndex + 1) % 3`,bidTurn/bidOrder 从该索引起。首次开局仍可随机或从 0 起(保持现状即可,重点是"再来一局"轮换)。

### 6.（bug）散桌后重新 /ddz，未凑齐人就显示旧手牌
现状:散桌(disband)清了服务端状态,但前端 ddz.hand 未清;重新 /ddz 进入 waiting,前端仍残留上一局手牌,在没发牌时就显示。
改法:前端在收到 phase==="waiting"(或 "none")的 ddz_state 时,清空 ddz.hand 与手牌条。确保只有 bidding/playing 阶段、服务端下发 ddz_hand 后才显示手牌。散桌广播的 phase:"none" 已收起 bar,此处补清 hand 数据。

### 7.（增强）散桌时广播本桌最终排行榜
现状:散桌(ddz_disband,含结算后主动散桌与中途「退出牌局」)只广播一条散桌文字,不展示这一桌的战绩。
改法:散桌清零(clearGame)**之前**,先广播本桌最终排行榜——按 scores 累计分从高到低列出三人及分数。
- 中途退出:进行中的当前这局作废(本就不结算、不计分),但之前已结算各局的累计分真实保留,并计入这份排行榜。
- 仅当 scores 有非零记录(即至少完整打完一局)才发榜;若一局都没结算过(累计全 0/空),只广播散桌、不发榜(避免全 0 榜)。
- 发榜后照常 clearGame 清零;后续重新 /ddz 是全新一桌,累计分从 0 起算。
- 广播格式示例:`本桌战绩 — 小明 +6，小刚 0，小红 −6。牌桌已解散。`

## 影响面

- 服务端 src/worker.js:出牌校验文案(1)、settle 广播加剩余手牌(3)、出牌/过牌广播加三家剩余张数(4)、startBidding/游戏状态加 firstBidIndex 轮换(5)、disband 清零前发最终排行榜(7)。
- 前端 renderPage:settled 清手牌条(2)、waiting/none 清 hand(6)。
- 引擎 src/ddz.js:无需改动(纯规则不变)。
- 现有 51 测试需保持通过;新增针对再来一局轮换首叫、散桌发榜(有战绩发/无战绩不发)的集成断言。

## 非目标

- 不改核心规则(牌型、叫分、计分、压制)。
- 不加旁观、超时、AI。
- 不改部署;不加依赖;commit 不带 TRAE 署名。

## 测试策略

- 服务端:再来一局后 bidTurn 为上局首叫的下一座位(集成测试可断言 ddz_state.current 轮换)。
- 纯逻辑若抽取(如"下一个首叫座位"计算)可加 ddz.js 单测,否则在 DO 层断言。
- 前端清手牌条:静态 hook 检查 + 手动冒烟(沙箱无法交互,如实标注 NOT RUN)。
