# 上次阅读位置分隔线 — 设计文档

日期：2026-07-31
项目：Ptnook 聊天室(Cloudflare Workers + Durable Objects,单文件 src/worker.js 含 ChatRoom DO + 内嵌 HTML)

## 目标

让用户重新进房或切回窗口时,一眼看到"以上是新消息"的分隔线并自动定位到那里,快速回到离开期间错过的消息。纯前端、零后端、零账号,不打扰(不做弹窗/声音提醒)。

## 范围

纳入:
- 用 localStorage 按房间记住"上次读到的最后一条消息 ts"。
- 以**窗口失焦(blur)**为准更新"已读位置";另在离开房间 / 关闭页面时补存一次。
- 进房 / 窗口重新聚焦(focus)时,在第一条更新的消息前插入分隔线并滚动定位。
- 分隔线稳定保留,直到下次失焦→聚焦或重新进房才重算。

排除(YAGNI):
- 未读计数徽章、弹窗提醒、声音(用户明确嫌聒噪)。
- 跨浏览器 / 跨设备同步(纯 localStorage,单浏览器单房间)。
- 服务端改动、账号/持久身份。

## 数据(localStorage)

- key:`ptnook:lastread:<房间名>`。
- value:该房间"上次读到的最后一条消息 ts"(数字,来自消息的 ts)。
- 按房间名隔离,各记各的。

## "已读位置"何时更新(以窗口失焦为准)

- 窗口 `blur` 时:把当前房间已显示的最后一条消息的 ts 存入 localStorage。
- 离开房间(点「离开」)/ 关闭页面(`beforeunload`)时:再存一次当前最后一条 ts,保证下次进来基准正确。
- 若当前无任何消息,不写(避免存入无意义值)。

## 分隔线何时出现

- **进房时**:渲染完历史后,读该房间 lastread;找到第一条 `ts > lastread` 的消息,在其前插入分隔线 `—— 以上是新消息 ——`,并滚动定位到分隔线(而非底部)。若无更新消息(全读过 / 无 lastread),不插线,正常滚到底。
- **窗口 `focus` 时**:用失焦时存下的 lastread,同样在第一条更新消息前插入分隔线并滚动定位。
- 分隔线稳定保留(方案 A):插入后不随普通新消息变动;仅在下次失焦→聚焦或重新进房时重算——重算前先移除旧分隔线,再按新基准插入。

## 边界与约束

- 同一时刻最多一条分隔线;插入新的前先移除已有的。
- 分隔线是纯前端 DOM,不发送给服务端、不进历史、不参与广播。
- 仅缓存最近 50 条:离开期间若超 50 条,更早的本就看不到,分隔线落在可见的第一条新消息前——既有上限的自然结果,不额外处理。
- 所有消息 nick/text 渲染仍走 `textContent`;分隔线是静态文案,同样 textContent,不破坏 XSS 安全。
- localStorage 不可用时(隐私模式等)静默降级:功能失效但不报错、不影响聊天。

## 关键判定逻辑(可测纯函数)

抽一个纯函数用于单测,建议签名:
- `firstUnreadIndex(items: Array<{ts:number}>, lastReadTs: number): number`
  - 返回第一条 `ts > lastReadTs` 的索引;若不存在或 lastReadTs 为空(null/undefined/0 视语义),返回 `-1`(表示不插线)。
  - 放在 `src/messages.js`(现有纯函数模块)以便复用现有 vitest 配置。

## 测试策略

- 纯函数 `firstUnreadIndex`:vitest 单测覆盖——有更新消息(返回正确索引)、全部已读(返回 -1)、无 lastread(返回 -1)、边界(等于 lastReadTs 的消息算已读,不算新)。
- 现有 20 个服务端测试保持通过(本功能不动服务端)。
- blur/focus/beforeunload 绑定、DOM 插入、滚动定位、localStorage 读写:纯浏览器行为,沙箱无法交互冒烟——以静态 hook 检查 + 手动冒烟为主,如实标注 NOT RUN。
