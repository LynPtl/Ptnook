# 即时网页聊天室 — 设计文档

日期：2026-07-31

## 目标

一个免登录、房间口令制的即时纯文字聊天室，供小范围（自己人）使用。部署与维护尽量走免费方案，零运维。

## 核心决策（需求确认结论）

- **内容**：仅纯文字消息。
- **历史**：纯即时，不保存历史。刷新/重进只看之后的消息。
- **口令**：房间名即口令，知道房间名即可进入，无单独密码。
- **身份**：进房前填昵称，消息显示昵称。
- **部署**：Cloudflare Workers + Durable Objects。零运维、不休眠、免费额度充足。

## 1. 架构

```
浏览器 (单页 HTML/JS)
   │  1. 打开页面，填「房间名 + 昵称」
   │  2. 建立 WebSocket 连接 → /room/<房间名>?nick=<昵称>
   ▼
Cloudflare Worker (入口)
   │  按房间名路由到对应的 Durable Object
   ▼
Durable Object (每个房间一个实例)
   - 持有该房间所有活跃 WebSocket 连接
   - 收到一条消息 → 广播给房间内所有人
   - 不存历史（纯即时）
```

- 一个房间 = 一个 Durable Object，房间名即口令。
- 前端是单个 HTML 文件（内嵌 JS/CSS），由 Worker 直接返回，无需单独托管。

## 2. 用户交互流程

进房前（表单页）：
- 输入框：`房间名`、`昵称`；「进入」按钮。
- 不做任何账号校验。

进房后（聊天界面）：
- 顶部：当前房间名 + 在线人数。
- 中部：消息滚动区。
- 底部：输入框 + 发送按钮（回车发送）。
- 系统消息：某人加入/离开显示灰色系统提示。
- 断线自动重连（指数退避）。

离开：关闭页面或点「离开」即断开，在线人数实时更新。

## 3. 消息格式与错误处理

WebSocket 消息（JSON）。

客户端 → 服务端：
```json
{ "type": "chat", "text": "大家好" }
```

服务端 → 客户端（广播）：
```json
{ "type": "chat", "nick": "小明", "text": "大家好", "ts": 1730370000000 }
{ "type": "system", "text": "小红 加入了房间", "ts": 1730370001000 }
{ "type": "presence", "count": 3 }
```

- `nick` 在建立连接时通过 URL 参数带上：`/room/<房间名>?nick=<昵称>`。
- 服务端只广播，不落库；`ts` 由服务端打。

约束与错误处理：
- 房间名 / 昵称长度限制（各 ≤ 32 字符）并做转义，防止超长/XSS。
- 单条消息长度限制（≤ 2000 字符）。
- 昵称为空回退为「访客」。
- 连接异常/关闭 → 前端指数退避自动重连。
- 服务端对消息做基本 JSON 校验，非法消息忽略。

## 4. 项目结构与测试

```
chatroom/
├── src/
│   └── worker.js        # Worker 入口 + Durable Object（房间）+ 内嵌前端页面
├── test/
│   └── room.test.js     # Durable Object 逻辑单测
├── wrangler.toml        # Cloudflare 部署配置
├── package.json
└── README.md            # 本地运行 + 部署步骤
```

本地开发与部署：
- `npx wrangler dev` 本地跑（含 WebSocket），浏览器直接测。
- `npx wrangler deploy` 一键部署，得到 `*.workers.dev` 网址。
- 免费：Workers 免费额度 + Durable Objects 免费额度。

测试：
- `vitest` + `@cloudflare/vitest-pool-workers` 测 Durable Object 核心逻辑：广播、加入/离开的 presence 计数、消息校验/转义、超长截断。
- 手动冒烟：两个浏览器窗口进同一房间验证实时互通。

## 非目标（YAGNI）

- 不做账号/登录、不做图片/文件、不做历史持久化、不做端到端加密、不做管理后台。
