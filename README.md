# 即时聊天室

免登录、房间名即口令的即时纯文字聊天室，支持斗地主、德州扑克及 AI 跑团。普通聊天只保留临时消息缓存；跑团使用独立身份和长期存档。部署在 Cloudflare Workers + Durable Objects。

## 本地运行

    npm install
    npm run dev

浏览器打开 wrangler 提示的本地地址，填房间名 + 昵称即可聊天。开多个窗口用同一房间名测试。

## 测试

    npm test

部署前建议跑完整校验：

    npm run verify

## 部署（免费）

1. 安装并登录：`npx wrangler login`
2. 部署前校验：`npm run verify`
3. 一键部署：`npm run deploy`
4. 部署完成后得到 `https://chatroom.<你的子域>.workers.dev`，把地址发给朋友即可。

聊天室可按小范围免费额度部署；跑团的长期存储和第三方模型推理可能产生费用，应配置模型预算并核对服务商账单。

## 用法

- 房间名就是口令：知道房间名的人填入即可进入同一房间。
- 昵称留空会显示为「访客」。
- 关闭页面即离开，其他人会看到离开提示与实时在线人数。
- 进房会看到该房间最近 50 条消息（每个房间独立，纯即时滚动，不做永久历史）。
- 消息显示发送时间（时:分）。
- 输入框支持多行：Enter 发送，Shift+Enter 换行。
- 房间在无人 30 分钟后自动清除这 50 条缓存，避免同名房间被后来者看到旧消息。
- 切走窗口再切回（或重新进房）时，会在第一条未读消息前显示「以下是新消息」分隔线并自动定位（记录在本浏览器本地，按房间区分）。
- 斗地主：在聊天框输入 `/ddz` 发起，另外两人点【加入牌桌】，满 3 人开局。抢地主、出牌、结算与累计分都在聊天流里显示，自己的手牌显示在输入框上方，点牌选中后点【出牌】或【过】。散桌/退出会清零累计分，「再来一局」则保留累计分继续算账。
- 德州扑克：在聊天框输入 `/poker` 发起牌桌，另外 1~2 人点【加入牌桌】（2~3 人），点【下一手】开局。小盲 0.5bb、大盲 1bb，每人初始 50bb，No-Limit 玩法（过牌/跟注/下注/加注/弃牌/全下），完整主池+边池结算，摊牌 7 选 5 比大小。筹码输光可在手间点【buy-in】领 50bb 复活。自己的底牌只在自己视角显示，牌桌状态与进展全桌可见。一个房间同一时刻只跑一种桌游（斗地主、德州或跑团）。

## AI 跑团（内测）

点击聊天室的【跑团】或输入 `/trpg`，也可直接访问 `/trpg`。

1. 建立玩家身份，保存恢复码；恢复码持有者能够控制该身份的全部角色，勿发到聊天中。
2. 创建《雾钟镇来信》战役，将邀请口令交给朋友，批准申请。
3. 每人创建角色、提出并确认队友关系，至少两人准备后填写房间名并开始。
4. 正式行动与场外讨论分开。全队提交后确认风险，系统掷骰并保存结果，AI 只负责理解与叙述。
5. 可暂停、恢复、查看线索与承诺、导出公开日志；战役不参与空房 30 分钟清理。

### 模型配置

使用支持 Chat Completions 风格 JSON 接口的服务商，由部署管理员统一配置。当前未指定默认服务商，也不内置模型密钥；未配置时可建角色和战役，但不能开始冒险。

本地在已被 Git 忽略的 `.dev.vars` 配置以下项目，真实密钥不要写入 `wrangler.toml` 或提交：

| 配置 | 含义 |
|---|---|
| `TRPG_AI_URL` | 服务商提供的完整 HTTPS Chat Completions 接口地址，不接受重定向 |
| `TRPG_AI_KEY` | 服务端模型密钥，通过 Bearer 发送 |
| `TRPG_AI_MODEL` | 服务商支持的模型名称 |
| `TRPG_AI_PROVIDER` | 向玩家公开的真实服务商名称 |
| `TRPG_AI_POLICY` | 向玩家展示的数据处理政策说明或官方政策地址 |
| `TRPG_CAMPAIGN_TOKENS` | 可选，每战役每日 token 上限，默认 1000000 |
| `TRPG_GLOBAL_TOKENS` | 可选，整个部署每日 token 上限，默认 2000000 |

线上密钥使用 `npx wrangler secret put TRPG_AI_KEY` 交互设置；其他非敏感项目可通过部署变量设置。修改配置、迁移和真实部署应单独确认，不由测试命令执行。

接口需要支持 `messages`、`response_format: { type: "json_object" }`、`max_tokens`，响应为 `choices[0].message.content` 中的 JSON 文本。预算按 UTC 自然日重置，所有尝试均计费；超时或用量未知时保留预留额度。token 限额不等于货币消费上限，仍应设置服务商账单告警。

### 验证

- `npm run verify`：规则、权限、存档、多人状态和已有牌局回归。
- `npx wrangler deploy --dry-run`：打包校验，不部署。
- `node scripts/trpg-browser-smoke.mjs`：独立浏览器双人流程，使用本地模拟模型，不向第三方发送数据；需要 `playwright-core` 和本机 Chrome。可用 `PLAYWRIGHT_MODULE` 指定其 `index.mjs` 绝对路径，`CHROME_PATH` 指定浏览器路径。脚本使用本机端口 8791 和临时内存存档。

### 当前限制

这是可运行的内测实现，不是 PRD 全量验收版本：

- 自由行动会映射到当前场景允许的效果；不能映射的危险或多步骤行动需要澄清，尚不支持任意新剧情分支。
- 战斗支持固定动作、前后排、职业能力、倒地救助和撤离；战斗内自由场景交互、交涉与每回合 AI 战况汇总尚未实现。
- 三章包含可通达的场景、关系选择、线索及三种结局，但还不是经过 6–9 小时真人内测的成品模组；背景专属支线、复杂承诺履约与长期剧情质量仍需打磨。
- 模型目前采用用户主动重试，不执行自动格式修复；公开文案由模型生成，不能保证完全不出现叙事矛盾，发现问题可关联事件并使用权威判定简报纠正。
- 实时界面使用 5 秒轮询；模型预算预留按 UTF-8 字节保守估计，可能比模型真实 token 数更早触达上下文限制。
- 没有真实模型配置时，自动化与浏览器测试只能验证模拟模型链路，不能验证真实模型质量、延迟、价格和服务商兼容性。
- 匿名化历史文本、完整灾备导入、更多内容包和复杂个人关系不在本次已验证功能中。
