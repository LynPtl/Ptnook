# 斗地主（三真人可玩 + 计分）— 设计文档

日期：2026-08-03
项目：Ptnook 聊天室(Cloudflare Workers + Durable Objects,单文件 src/worker.js 含 ChatRoom DO + 内嵌 HTML,零依赖零构建)

## 目标与范围

在聊天室里加一个三人斗地主小游戏:`/ddz` 发起,凑齐 3 人开局,抢地主、出牌、结算并记每桌累计分。纯真人对战,与聊天并存。

不做:AI 托管 / AI 出牌提示 / `/cheat` 之类任何 AI 相关功能;旁观;超时托管;春天翻倍;四带二带两对;独立牌桌 UI;永久跨会话排行榜;账号登录。

## 一、架构与引擎分层

- 复用"一房间一 Durable Object"。在 ChatRoom DO 内新增一块斗地主游戏状态,与聊天并存(聊天照常,游戏是房间内叠加子系统)。
- **纯规则逻辑抽成独立可单测模块 `src/ddz.js`**(纯函数,不依赖 WebSocket/DO):发牌、牌型识别、牌型比较、枚举合法出牌、叫分流转、胜负与计分。
- DO 只负责:座位/连接管理、持有游戏状态、调用 `ddz.js` 裁决、给每个连接单独下发"该玩家视角"。
- `enumerateLegalPlays(hand, lastPlay)` 保留为纯函数:给定手牌与需压制的上一手,枚举所有合法出牌(含"要不起"→空)。它是服务端出牌校验与规则单测的基础。

## 二、游戏状态(存 DO storage,断线/休眠可恢复)

- 阶段 `phase`:`waiting`(招募) / `bidding`(叫分) / `playing`(出牌) / `settled`(结算)。
- 3 个座位:每座 `{nick, connId, hand:[], role: landlord|farmer|null, bid}`。
- `landlord`(地主座位)、`bottom`(底牌 3 张)、叫分记录。
- 出牌区:`lastPlay:{seat, cards, type}`、`current`(当前该谁)、连续 pass 计数。
- `scores`:每桌各玩家累计分(存 storage)。
- 游戏状态随房间空置 30 分钟清除(复用现有 alarm 清理)。

## 三、规则细节(已确认)

**人数/开局**:正好 3 人。房间输入命令 `/ddz` 发起,发起人自动占座位 1,系统广播招募;其他人点「加入牌桌」按钮入座,满 3 人自动开局。`waiting` 期间发起人可「取消」。

**发牌**:每人 17 张,留 3 张底牌(未定地主前不亮)。

**抢地主(标准叫分)**:随机定首叫,轮流选「叫1/叫2/叫3/不叫」;后叫者只能叫更高分或不叫;有人叫 3 或一轮结束→最高分者当地主,亮 3 张底牌并入手牌(20 张);全程无人叫→重新发牌重叫。底分 = 地主所叫分(1/2/3)。

**牌型(标准 + 四带二只保留带两单)**:
1. 单张
2. 对子
3. 三张
4. 三带一(三+1单)、三带对(三+1对)
5. 顺子(≥5 连续单牌,不含 2/大小王)
6. 连对(≥3 对连续,不含 2/大小王)
7. 飞机:连续≥2 组三张;不带 / 带单(每组带1单) / 带对(每组带1对);翼数匹配组数,不混;三张部分连续且不含 2/王;比大小只看三张主体
8. 四带二:四张 + 2 张单牌(**普通牌型,非炸弹**,只能压更大的同类四带二)
9. 炸弹:纯四张
10. 王炸:双王(最大)

**压制规则**:同类型比大小(顺子/连对/飞机需同长度);炸弹可压任何非炸;王炸最大;四带二不是炸弹、压不过炸弹。

**出牌(服务端权威强校验)**:轮到你→选牌出牌 或「过」。服务端引擎判定轮次、牌型合法性、是否压得过上一手;非法**只回操作者**一条错误提示,不改状态。两家连续「过」→出牌权回到最后出牌者,可自由出任意合法牌型。某人手牌出完→`settled`。

**计分(标准计法,先不做春天)**:
- 底分 = 地主叫分;每个炸弹、王炸各 ×2(翻倍)。
- 地主赢:地主 +底分×倍数×2,两农民各 −底分×倍数;地主输则符号相反。
- 结算后更新每桌累计分并广播。

**信息可见性**:自己手牌仅本人可见;别人手牌不可见(只显示剩余张数);每一手打出的牌全桌可见;底牌定地主后亮给全桌。**不做旁观**——仅 3 名上桌玩家看到牌局,房间其他人照常聊天、看不到牌局。

**断线/超时**:出牌**不限时**(一直等当前玩家)。某玩家断线→**保留座位、牌局暂停等重连**;重连后服务端重新下发"你的手牌 + 当前局面"继续。

## 四、交互与消息协议

**交互形态**:发起用命令 `/ddz`;**游戏内所有操作(加入牌桌、叫分、出牌、过、再来一局、取消)全走点选 + 按钮,无命令**。牌局进展信息走系统广播,滚在消息流里(牌桌三人可见)。**不做独立牌桌 UI**:自己的手牌固定显示在输入栏上方的"手牌条";牌是服务端给的结构化数据,前端拼显示,全走 `textContent`(不破坏 XSS)。大小王显示「小王」「大王」,其余显示点数(3~10、J、Q、K、A、2)。手牌条可点选高亮,选好点「出牌」/「过」。轮到叫分时手牌条上方出现「叫1/叫2/叫3/不叫」按钮。

**消息协议(JSON,与现有 chat/system/... 并存)**

服务端→客户端:
- `{type:"ddz_state", phase, seats:[{nick,cardCount,role,bid}], landlord, bottom?, current, lastPlay:{nick,cards,type}, scores}` — 公共牌局状态,广播给 3 名玩家。
- `{type:"ddz_hand", cards:[...]}` — **仅发给本人**的手牌。
- `{type:"ddz_error", text}` — 仅发给操作者的非法提示。
- 关键节点(招募/叫分/出牌/结算)同时复用现有 `system` 文案广播,便于房间可读。

客户端→服务端:
- `{type:"ddz_start"}`(对应 `/ddz` 命令触发)
- `{type:"ddz_join"}`、`{type:"ddz_cancel"}`
- `{type:"ddz_bid", value:0|1|2|3}`(0=不叫)
- `{type:"ddz_play", cards:[...]}`、`{type:"ddz_pass"}`
- `{type:"ddz_again"}`(再来一局)

## 五、前端 UI(极简,无独立牌桌)

- 聊天界面基础上:输入栏上方增加"手牌条"(仅本人可见,随出牌更新;可点选)。
- 轮到操作时,手牌条区域显示对应按钮:叫分阶段「叫1/叫2/叫3/不叫」;出牌阶段「出牌」「过」;招募阶段「加入牌桌」「取消」;结算后「再来一局」。
- 牌局进展(谁叫分、谁出了什么、轮到谁、剩几张、结算与累计分)走系统广播消息,滚在消息流。
- 游戏中仍可正常发聊天。

## 六、一局结束处理

- 结算展示本局输赢 + 每桌累计分(广播)。
- 「再来一局」:三人都在座→快速重开(重新发牌叫分);有人离席→回到 `waiting` 等补人或「取消」解散。

## 七、测试策略

- `src/ddz.js` 纯函数(重点,充分单测):牌型识别(每型 + 反例)、牌型比较(含炸弹/王炸压制、四带二非炸)、`enumerateLegalPlays`(含要不起)、叫分流转、发牌(54 张不重不漏)、计分(底分×炸弹翻倍、地主/农民得失符号)。
- DO 层集成测试(vitest-pool-workers):主流程(发起→满员→叫分→定地主→出牌→结算)、非法出牌被拒、断线重连拿回手牌与局面。
- 前端手牌条/按钮交互:沙箱无法交互,静态 hook 检查 + 手动冒烟,如实标注 NOT RUN。
