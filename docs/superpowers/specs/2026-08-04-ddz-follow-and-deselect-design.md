# 斗地主跟牌哲学改动 + 取消选中按钮 — 设计文档

日期：2026-08-04
项目：Ptnook 聊天室斗地主（master 分支，src/ddz.js 有 chooseHint/decompose/structureScore，src/worker.js 前端手牌条，81 测试）

## 背景与目标

用户对跟牌提示的期望：**只要有能压过上家的牌就必须亮出来**（哪怕要拆牌），但**有不拆的选项优先出不拆的**；不再"为了留炸而不提示"。这覆盖当前实现的跟牌规则 1/2（现在排除炸弹/王炸、只有炸能压才提示炸）。

外加一个前端小改：手牌条加「取消选中」按钮，一键清空当前选中。

## 一、跟牌逻辑改动（chooseHint，last 非空）

**现状**（要改掉）：
- 规则 1：候选中**排除**炸弹/王炸，选破坏度最低+最小 rank。
- 规则 2：只有炸弹/王炸能压时，才提示最小炸弹 / 王炸。

**新逻辑**（合并规则 1/2 为单一排序）：
- 候选 = `enumerateLegalPlays(hand, last)`（所有能压过上家的合法牌，**包含炸弹/王炸**）。
- 候选为空 → 返回 null（DO 侧回 ddz_error「没有能压过的牌，只能过」）。
- 否则按以下**排序键**取第一手（升序，越前越优先）：
  1. **破坏度**（低者优先）：出该手后剩余手牌的散牌数 `structureScore(remaining)`，越小越好（不拆成型牌组）。
  2. **非炸优先**（同破坏度时）：普通牌型排在炸弹/王炸前面。用一个布尔键 `isBombOrRocket(play) ? 1 : 0`，0 优先。
  3. **牌型点数最小**（rank 升序）：`identifyPlay(play).rank`。
- 只要有能压的就必然返回一手（不因"要拆牌/要用炸"而不提示）；平手时普通牌优先于炸，且出最小。

**规则 0（一手走完，最高优先）不变**：整手是合法牌型且能压过 last → 直接全出。
**自由出规则 3 不变**（上一批已修好）。

实现方式（建议）：把三个键组成可比较的元组，对候选做稳定排序或线性扫描取最优：
- `keyOf(play) = [ structureScore(removeCardsArr(hand, play)), isBombOrRocket ? 1 : 0, identifyPlay(play).rank ]`
- 取字典序最小的 play；`structureScore` 与 `removeCardsArr` 已存在，复用。
- `isBombOrRocket(play)`：`const t = identifyPlay(play).type; return t === "bomb" || t === "rocket";`

## 二、前端「取消选中」按钮（src/worker.js renderPage）

- 在出牌阶段（playing）且轮到自己时，出牌区按钮加一个「取消选中」，与「出牌」「提示」「过」并列。
- 点击：清空 `ddz.selected = {}` 并 `renderHand()`（去掉所有高亮）。
- 不发任何服务端消息，纯前端。

## 三、影响面

- src/ddz.js：改 chooseHint 的跟牌分支（合并规则 1/2 为单一排序，含炸弹/王炸候选、非炸优先键）。规则 0、自由出规则 3、decompose、structureScore 不变。
- src/worker.js：renderDdz 的 playing 分支加「取消选中」按钮 + 一个清空选中的小函数（或内联）。
- 现有 81 测试须通过；跟牌相关旧测试若期望随新逻辑改变，按新正确行为更新（不得弱化）。
- 新增：跟牌"能压就亮（含要拆的）"、"同破坏度非炸优先"、"只有炸能压也亮炸"的单测。

## 四、测试策略

- chooseHint 跟牌新逻辑单测：
  - 有不拆的普通牌能压 + 有拆牌能压 → 返回不拆的（破坏度优先）。
  - 同破坏度下普通牌 vs 炸弹都能压（都不拆）→ 返回普通牌（非炸优先）。
  - 只有拆牌才能压（无不拆选项）→ 仍返回拆牌那手（能压就亮，不再返回 null）。
  - 只有炸弹/王炸能压 → 返回炸弹（最小）/王炸。
  - 真要不起（没有任何能压）→ 返回 null。
  - 规则 0 仍优先：整手能压 → 全出。
- 前端「取消选中」：静态 hook 检查 + 手动冒烟（沙箱无法交互，如实标注 NOT RUN）。
- DO ddz_hint 现有测试保持；如期望变化按新行为更新。

## 五、非目标

- 不改自由出规则 3、不改规则 0、不改 decompose。
- 不做多步搜索/最优策略（跟牌仍是启发式排序）。
- 不改部署、不加依赖；commit 不带 TRAE 署名。
