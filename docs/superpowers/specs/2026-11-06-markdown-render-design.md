# Markdown 渲染（最小内联集）— 设计文档

日期：2026-11-06
项目：Ptnook 聊天室(Cloudflare Workers + Durable Objects,单文件 src/worker.js 含 ChatRoom DO + 内嵌 HTML,零依赖零构建)

## 目标

让聊天消息支持**最小内联 Markdown**（粗体/斜体/行内代码/删除线/自动链接），在**不引入依赖、不引入构建、不破坏 XSS 安全**的前提下完成。

本需求自 `2026-07-31-chat-experience-tier1-design.md` 起即被列为推迟项，原文："Markdown 渲染(以后单独 brainstorm,重点做 XSS sanitizer 选型)"。本文档即那次 brainstorm 的结论。

## 范围

纳入（块级 + 行内）:

块级（2026-11-06 第二期新增）:
- `#`～`######` → `<h1>`～`<h6>`（七级及以上按段落处理）
- `- ` / `* ` / `+ ` → `<ul><li>`
- `1. ` / `1) ` → `<ol><li>`
- `> ` → `<blockquote>`（连续 `>` 行合并为一个引用）
- `---` / `***` / `___` → `<hr>`
- ` ``` ` 围栏 → `<pre><code>`，**内部只转义、不解析任何行内语法**
- 其余非空行 → `<p>`（多行保留换行，由 `white-space: pre-wrap` 呈现）

行内:
- `**文字**` → `<strong>`
- `*文字*` → `<em>`
- `` `文字` `` → `<code>`
- `~~文字~~` → `<del>`
- `https://...` / `http://...` → `<a>`（自动链接，仅 http/https）

白名单标签全集：`h1..h6` `p` `ul` `ol` `li` `blockquote` `pre` `code` `hr` `strong` `em` `del` `a`。
属性仍只有一个常量拼接的 `href`（另加固定的 `target` / `rel`）。

排除（YAGNI / 明确不做）:
- 表格。
- 嵌套列表（一层即可）。
- **图片 `![]()`：不解析，原样显示为文本**。理由：README 定位「仅纯文字消息」；外链图片可被用于追踪 IP（加载即泄露）。
- 链接语法 `[文字](url)`：不实现。`**` 内的 `[...](javascript:...)` 不会被转成链接，仅作纯文本处理。
- Markdown 渲染开关/用户偏好设置（不做开关，一律渲染）。
- 服务端改动（协议、存储、广播全部不动）。

## 一、架构选择：服务端 vs 前端

**结论：渲染放前端，函数放独立模块，纯函数、可单测。**

- 逻辑归属写成独立模块 `public/markdown.js`（纯函数，不依赖 WebSocket/DO/DOM），
  与 `ddz.js` / `holdem.js` 的分层一致（纯规则逻辑从 worker.js 抽离以便充分单测）。
  第二期从 `src/` 移至 `public/`，作为静态资源单一源（见“三、接线方式”）。
- 该模块被 worker.js 内嵌前端 `<script>` 引用：`worker.js` 通过 ES module `import` 引入，
  前端脚本作为内嵌字符串无法 import —— 因此**在 worker.js 内以字符串拼接方式注入**：
  见"三、接线方式"，不引入打包器。
- 渲染时机：消息到达时（含历史 items），与现有 `addChat` 对齐。

选前端而非服务端的原因：
- 历史/重连/新消息三条路径都走同一个 `addChat`，只需改一处，无需改协议与存储。
- 服务端不落 HTML，`history` 里存的仍是原文，避免"存 HTML 又被二次渲染"的风险。
- 零协议改动 = 零兼容成本（旧客户端不会收到意外字段）。

## 二、安全模型（本设计核心）

### 为何不需要通用 sanitizer

语法锁死为「5 种行内 + 无图片 + 无 `[text](url)`」后，**输出标签是固定枚举**：
`strong` `em` `code` `del` `a`。用户输入**永远只出现在标签内容位置，或已被转义的引号内**，
从不进入属性名位置，也无法构造新的属性。

因此本设计**不采用"匹配危险模式再过滤"**（易漏、需维护黑名单），而采用
**"先整体转义，再仅对白名单标记套标签"**——只构造已知安全结构。

### 顺序即保证（安全关键）

```
1. 剔除原文中的 NUL                     防伪造占位符
2. 按行识别块级结构                      此阶段不转义（否则 > 变 &gt;，引用正则失效）
3. 围栏整块抽走，内部只 escapeHtml        不解析任何行内语法
4. 块内容的每一行先 escapeHtml            & < > " ' 全部实体化
5. 行内代码抽为占位符                     内部不再被后续规则解析
6. 依次套 strong / em / del              此时已无 < > " '，无法注入
7. 自动链接                              仅 http/https，href 由常量模板拼接
8. 回填 code 占位符
```

关键点：块级识别必须发生在转义**之前**。早期实现先整体转义再匹配块级，
导致 `>` 已变成 `&gt;`，引用永远无法识别（已实测踩中）。

### 转义表

| 字符 | 实体 |
|---|---|
| `&` | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

### 自动链接约束

- 仅接受 `^https?://`（大小写不敏感）；`javascript:` / `data:` / `vbscript:` 一律不转链接。
- `<a>` 的属性 `href` / `target` / `rel` 由**字面量常量**拼接，用户文本无法控制。
- 必须带 `rel="noopener noreferrer"`，否则 `target="_blank"` 可经 `window.opener` 反向控制原页面。
- 链接 URL 本身已经过步骤 1 转义，`&` 会变成 `&amp;`，符合 HTML 属性语义，可正确解析。
- 链接 URL 的终止规则分两级：
  - 匹配阶段即排除空白、`<`、`>`、`` ` ``、`"` 与全角标点（`，。；：！？、）】」』…`），
    否则贪婪匹配会越过全角逗号把后续中文吞进 URL。
  - 匹配后从尾部剥离 ASCII 句末标点（`.,;:!?'*~_]`）与不成对的右括号，
    因为 URL 内部允许 `.` 与 `()`，不能在字符类里一刀切。
  - **历史缺陷（已修）**：早期用 `[^\s]+`，会把上一步生成的 `</strong>` 吞进 href，
    产出 `href="https://example.com</strong>"`，点击得到无效地址。
    现用 `[^\s<>`"…]+` 排除尖括号与反引号，`</strong>` / `</del>` / `</em>` 与 code 占位符边界均不再污染。

### 行内代码的占位符策略

用不可见字符 `\u0000<序号>\u0000` 占位。用户原文中的 `\u0001`、`\u0002` 在步骤 1 不转义，
故实现时需**先剔除原文中的 `\u0000`**，防止伪造占位符造成注入或错位。

强调嵌套使用独立的 `\u0001`/`\u0002` 占位符。这三个控制字符均在 `renderMd`
入口处从原文剔除，用户无法伪造。（开发中实测踩中：未剔除 `\u0001/\u0002` 时，
输入 `**a**\u00010\u0002` 会命中 slots[0] 复制已渲染内容。）

### 强调解析：对称优先、由内到外

旧实现用两条独立正则（先 `**` 后 `*`），两个缺陷：
- `5 * 3 * 2 = 30` 被误配为斜体（只看两侧各有一个 `*`，不判断字符性质）
- `**a *b* c**` 的粗体不生效（内层 `*b*` 先被 em 消耗，外层无法配对）

现改为反复寻找「最内层且两侧标记数对称」的配对，替换为占位符后再找外层：

| 输入 | 输出 |
|---|---|
| `**a *b* c**` | `<strong>a <em>b</em> c</strong>` |
| `*a **b** c*` | `<em>a <strong>b</strong> c</em>` |
| `*a**b**c*` | `<em>a<strong>b</strong>c</em>` |
| `***a***` | `<em><strong>a</strong></em>` |
| `5 * 3 * 2 = 30` | 原样（不产生 `em`） |

边界约束：
- 开标记右侧不能是空白，闭标记左侧不能是空白（CommonMark 左右分隔符判定）。
- 嵌套**不跨手动换行**：每个 `\n` 独立处理，避免长文本跨段远距离误配。

## 三、接线方式（唯一突破 textContent 之处）

现状 `src/worker.js` 的 `addChat`：

```js
b.textContent = t;
```

改为：

```js
b.innerHTML = renderMd(t);
```

**这是全项目唯一允许承载服务端数据走 HTML 的位置**，必须在代码处写注释说明理由，
防止后人按"一律 textContent"的旧约定误改回。

其余所有位置（nick、system 消息、牌面、底牌、按钮文案）**保持 textContent 不变**。

### 引入方式：`[assets]` + ES module（2026-11-06 第二期改定）

渲染器唯一源为 `public/markdown.js`，经 `wrangler.toml` 的 `[assets]` 以静态资源提供，
前端用 `<script type="module">import { renderMd } from "/markdown.js"` 引入。

**为何不再用 `renderMd.toString()` 注入**（早期方案，已废弃）：
`toString()` 注入要求函数体内不得出现任何嵌套函数，因为 wrangler 的 esbuild（keepNames）
会把嵌套函数改写成 `__name(...)` 调用，而该辅助函数在内联 `<script>` 中不存在，
导致整段聊天脚本崩溃。块级解析需要循环状态机与辅助函数，与该约束根本冲突。
迁移到 ES module 后约束解除，且仍是单一源、零依赖、零构建。

**实测结论**（wrangler 4.116，本地 dev）：
- `GET /` 仍走 Worker（assets 未命中时回落），返回 `text/html`。
- `GET /markdown.js` 返回 `text/javascript; charset=utf-8`，浏览器可作 module 加载。
- 缓存默认 `Cache-Control: public, max-age=0, must-revalidate` + ETag，
  **升级后无旧版粘滞问题**，无需额外失效配置。
- `/room/:name` 仍走 Durable Object，非 WebSocket 请求返回 426。
- 静态资源不经 esbuild 处理，原样返回（不会出现 `__name` 等注入）。

## 四、与现有行为的兼容

- **多行输入**：`.body` 已有 `white-space: pre-wrap`，`innerHTML` 不与之冲突，换行照常保留。
  所有正则均带 `[^\n]`，跨行不会被误匹配（行内代码不跨行）。
- **`/ddz`、`/poker` 命令**：在 `sendMessage` 中先行拦截并 `return`，不经过渲染，无影响。
- **滚动/贴底、新消息分隔线、未读定位**：均不依赖 `.body` 的文本节点结构，不受影响。
- **历史缓存 50 条**：存原文，不改。
- **XSS 现状不回退**：nick、system 仍 textContent。

## 五、测试策略

新增 `test/markdown.test.js`（vitest，与现有 4 个测试文件同风格）：

1. **语法正例**：5 种语法各自单独与混排。
2. **XSS 反例（必须具备）**：
   - `<script>alert(1)</script>` → 全实体化
   - `<img src=x onerror=alert(1)>` → 全实体化
   - `**<script>**` → strong 包裹下仍为转义文本
   - `<a href="javascript:alert(1)">a</a>` → 全实体化
   - `</div><svg onload=alert(1)>` → 全实体化
   - `` `<script>` `` → code 内仍为转义文本
   - `javascript:alert(1)` 与 `[x](javascript:alert(1))` → 不生成 `<a>`
   - 属性逃逸 `" onmouseover="alert(1)` → 引号实体化
   - 伪造占位符 `\u00001\u0000` → 不产生注入
3. **边界**：未闭合 `*`、`**` 嵌套、`*` 紧邻非空格、超长文本、空字符串、未闭合围栏。
4. **块级**：`h1..h6`、七级不成标题、`#标签` 不成标题、`ul`/`ol`、`blockquote` 多行合并、
   `hr` 三种写法、围栏内部不解析、围栏内 XSS 转义、未闭合围栏回退为段落、
   块级内可含内联标记、空行分隔不产生空段落。
5. **链接边界（回归）**：`href` 严格等于 URL（裸链接 / `**` / `~~` / `*` 四种包裹）、
   行内代码内不产出链接、链接后紧跟中文标点不吞入。
6. **回归**：`<` 在 code 内显示为 `&lt;` 且不丢字符。
7. **幂等/原文不变**：渲染不修改 `messages.js` 的 `sanitizeText` 行为，`test/messages.test.js` 保持全绿。

前端渲染结果（真实浏览器内视觉）沙箱无法交互验证，如实标注 **NOT RUN**，以手动冒烟补充。

## 六、非目标提醒

- 不改部署方式（仍 `npm run deploy`）、不加第三方依赖、不引入构建步骤。
- 不做完整 Markdown、不做图片、不做开关。
- 服务端协议/存储/广播零改动，`test/room.test.js` 等既有测试必须保持全绿（当前 147 个用例）。
